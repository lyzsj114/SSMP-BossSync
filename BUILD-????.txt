SSMP 0.3.1.2 存档同步修复源码

基线：Extremelyd1/SSMP，提交 b62a2f4d5f75fc32c8f3f16d9734049223136d20（PR #99）。
在此基线上保留所给 scene-save 包的房主克隆、空值和 profileID 隔离行为，修复物品字段传输、加载时序及持久化。
许可证：LGPL-2.1-or-later，见 LICENSE。修改日期：2026-10-24。

构建环境：Windows x64，.NET SDK 9.0.319，LangVersion=preview（基线代码使用 field 关键字）。
锁定游戏引用：Silksong.GameLibs 1.2.0-silksong1.0.30000；依赖见 SSMP/packages.lock.json。

客户端：
  dotnet build SSMP/SSMP.csproj -c Release
独立服务端：
  dotnet publish SSMPServer/SSMPServer.csproj -c Release -r win-x64 --self-contained false -o release-server
回归检查（需要自己的正版游戏 Managed 目录，不在源码包内分发）：
  dotnet run --project SSMP.SaveSync.Tests/SSMP.SaveSync.Tests.csproj -c Release -p:GameManagedPath="C:/你的游戏路径/Hollow Knight Silksong_Data/Managed"

首次构建需要还原项目内声明的 NuGet 依赖。客户端依赖现有 BepInEx 安装；独立服务端运行需要 .NET 9 x64。
源码包不包含游戏程序集、游戏反编译结果、真实存档、联机密钥或用户日志。

实现摘要：
- 为 17 个复合字段添加受限 JSON 编解码，使用本地字段类型重建原生对象和运行时字典。
- 主菜单连接先选本地槽，再用 GameManager.SetLoadedGameData 安装服务端快照，最后 ContinueGame。
- 初始同步暂停回传、缓冲增量，场景进入时刷新工具/纹章缓存并建立深比较基线。
- 保留本地 profileID；旧个人记录仅补缺失的复合字段，不自动覆盖已有个人进度。
- 客户端协议标记拒绝旧版混连；复合数据可经 modsav 和独立服务端 save.json 往返。
- 游戏内房主随原生保存落盘；独立服务端每 5 秒及正常停止时保存，保留 .bak。
- 网络更新和保存快照访问使用同一锁；仅主线程读取游戏对象。

验证：73 项回归检查通过（含 1321 个同步字段的类型、完整快照及 JSON 往返）；独立服务端两次真实进程启动/自动保存/退出及重载通过。
退出命令返回码 5 是本项目 ExitCommand 的原有设计，不是崩溃。
未运行真实双人 Unity 游玩或 Boss 场景测试。

0.3.1.2 修正：
- memoryOrbs_Clover_18_A/B/C/D/E 与 memoryOrbs_Clover_19 改为 UInt64，网络协议标记升级为 2。
- 旧 JSON 中负的 32 位位图按低 32 位迁移，不把符号位扩展成假进度。旧版已经截掉的高位无法凭空恢复。
- 写 JSON 时正确处理 null 字符串，防止整份服务端保存失败。
- 客户端先排队初始化再公开 Connected 状态，主线程执行时才解析处理函数；注销会作废旧连接的排队包。
- 原生字段类型不符时日志明确打印字段名、实际类型、目标类型和数据长度。
- 独立服务端用 1321 字段合成存档进行两次进程启动/保存/关闭，64 位值精确保持一致。
